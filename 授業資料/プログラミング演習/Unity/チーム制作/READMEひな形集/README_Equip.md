## 担当した機能

### 1. プレイヤータイプの選択
- 剣・弓・魔法の中から、次のクエストで使うタイプを選びます。
- 選んだタイプは共通データ（`GameData.SelectedPlayerTypeId`）に保存され、ボス戦のシーンでそのタイプのプレイヤーが出てきます。

### 2. スキルの付け外し
- ショップで買ったスキルを、決定ボタンで「付ける ⇔ 外す」に切り替えます。
- 同時に付けられるスキルは 2 つまでです。画面上部に「スキル枠 1 / 2」のように表示し、枠がいっぱいのときは「先にどれかを外してください」と案内します。

### 3. 状態に合わせた表示

| スキルの状態 | 右側の表示 | 説明欄 |
|---|---|---|
| 未購入 | 未購入（暗い色） | スキルの説明 ＋「村人のショップで買えます。」 |
| 購入済み・付けている | 装備中（明るい色） | スキルの説明 |
| 購入済み・外している | 装備していません | スキルの説明 |

## 工夫したところ

### 付け外しを 1 行で切り替えた
「付けていれば外す、外していれば付ける」は、今の状態を `!`（否定）で反転させるだけで書けます。
`if` で 2 通り書くより短く、間違いも起きにくくなりました。

```csharp
int level = GameData.GetSkillLevel(e.skill);

if (level == 0)
{
    ShowMessage("まだ買っていません");     // 未購入なら付けられない
    return;
}

bool nextState = !GameData.IsSkillEquipped(e.skill);   // true ⇔ false を反転
if (!GameData.SetSkillEquipped(e.skill, nextState))    // 枠がいっぱいだと false が返る
{
    ShowMessage("スキル枠がいっぱいです。先にどれかを外してください");
}
```

### 「次に何をすればいいか」を案内した
未購入のスキルを選んだときは、説明欄に「村人のショップで買えます。」と表示しました。
ショップ担当とも相談して、ショップ側には「装備画面で付けると効果が出ます」と表示してもらい、**2 つの画面で行き来の案内がつながる**ようにしました。

### 一覧を「見出し＋行」で整理した
タイプ選択とスキル一覧を 1 つの画面に並べるので、`CreateHeader("スキルタイプ")` で見出しを入れて区切りました。
行ごとに「タイプの行か、スキルの行か」を覚えておき、決定ボタンを押したときの処理を分けています。

## 苦労したところと解決方法

| 問題 | 原因 | 解決 |
|---|---|---|
| 付け外ししても表示が変わらない | 状態を変えたあとに一覧を描き直していなかった | 変更のたびに一覧を更新するようにした |
| マージしたら、ほかの担当の変更とぶつかった（競合） | 同じ共通ファイルを複数人が編集していた | GitHub 上の Pull Request で差分を確認しながら解決した。`.meta` ファイルの役割も学んだ |
| 不要な `using` が入っていた | エディタの自動補完で追加されていた | 使っていない `using` を見直して削除するようにした |

## 学んだこと
- **共通データの読み書き**：画面は `GameData` を読み書きするだけにして、保存やボス戦への受け渡しは共通の仕組みに任せる作り方を学びました。
- **状態ごとの表示の出し分け**：同じ行でも、状態によって文字や色を変えることで、ひと目で分かる UI になることが分かりました。
- **他の担当との連携**：ショップ担当と案内文をそろえるなど、画面どうしのつながりを意識して作りました。
