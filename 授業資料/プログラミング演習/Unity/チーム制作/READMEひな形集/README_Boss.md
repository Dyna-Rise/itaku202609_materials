## 担当した機能

### 行動パターン（全 6 種）

| 技 | 内容 | 使う距離 |
|---|---|---|
| 咆哮 | 戦闘開始時と怒り状態になったときに吠える。近くのプレイヤーをひるませる | ― |
| 噛みつき | 口の当たり判定で攻撃 | 近距離 |
| ひっかき | 両翼の爪で攻撃。振りかぶりの間はプレイヤーへ向き直る | 近距離 |
| 突進（最大 3 連続） | プレイヤーを追いかけながら走り込む。曲がりながら減速して、次の突進へつなげる | 中距離 |
| ブレス | 口から火の玉を 3 発、扇状に吐く | 全距離 |
| 岩投げ | 放物線を描く岩を 5 個、扇状に投げる | 遠〜中距離 |

### 距離による技の選び分け
プレイヤーとの距離を「近・中・遠」の 3 段階に分けて、段階ごとに技の出やすさ（確率）を変えています。

```csharp
float distance = DistanceToPlayer;
int r = Random.Range(0, 100);         // 0〜99 のサイコロ。数字の幅が出やすさ

if (distance <= meleeRange)           // 近距離：小攻撃メイン
{
    if (r < 40) return Bite();
    if (r < 75) return Scratch();
    if (r < 88) return Breath();
    return Throw();
}
if (distance <= farRange)             // 中距離：突進が多め
{
    if (r < 55) return ChargeCombo();
    ...
}
```

### 怒り状態
HP が 50% を切ると咆哮して怒り状態になります。モーションの速さが 1.2 倍になり、攻撃後の休み時間が 0.6 倍に短くなるので、後半ほど手強くなります。

## 工夫したところ

### 攻撃の流れをコルーチンで「上から順に」書いた
1 つの攻撃を「モーション再生 → 何%まで待つ → 当たり判定 ON → 何%まで待つ → OFF → 休む」という手順で書きました。
待つ時間を**秒ではなくモーションの再生割合**で指定しているので、怒り状態でアニメーションが速くなっても、当たり判定がモーションとずれません。

```csharp
private IEnumerator Bite()
{
    yield return TurnToPlayer(0.5f, Walk);                 // プレイヤーの方を向く
    Play(BasicAttack);
    while (GetStateTime(BasicAttack) < 0.3f)               // 振りかぶり：軸合わせしながら少し踏み込む
    {
        FaceTowards(DirectionToPlayer, 1.5f);
        Move(transform.forward * 2.5f);
        yield return null;
    }
    biteHitbox.Begin(biteDamage, knockback: 1f);           // 当たり判定 ON
    yield return WaitStateTime(BasicAttack, 0.55f);
    biteHitbox.End();                                      // 当たり判定 OFF
    yield return WaitStateTime(BasicAttack, 0.95f);        // ほぼ最後まで待つ
    yield return Rest(RestTime(1.0f));                     // 隙（怒り時は短くなる）
}
```

### 「避けられる」ボスにした
- 攻撃の前には必ず予兆（振りかぶり・短い咆哮）を入れて、プレイヤーが反応できるようにしました。
- 突進の追尾は弱め（`chargeHoming = 0.35`）にして、横に回避すればかわせるように調整しました。
- 攻撃の後には「休み」を入れて、プレイヤーが反撃できる時間を作りました。

### ボス同士で共通の部分を親クラスに分けた
HP、被ダメージ、ひるみ、移動、モーション再生の待機などは、共通の `BossBase` クラスにあります。
ドラゴン固有の部分（どの技をいつ出すか）だけを `DragonNightmareBoss` に書いたので、別のボスを追加するときも技の部分だけ書けば済みます。

## 苦労したところと解決方法

| 問題 | 原因 | 解決 |
|---|---|---|
| 当たり判定が見た目より早く／遅く出る | 秒数で待っていたので、モーションの速さを変えるとずれた | モーションの再生割合（0〜1）で待つ `WaitStateTime` に統一した |
| 「最後まで待つ」で止まることがある | 再生位置が 1.0 ちょうどに届かないことがあった | 0.95 まで待つようにし、さらに 6 秒のタイムアウトを付けた |
| 突進が強すぎて避けられない | プレイヤーへの追尾が強すぎた | 追尾の強さ・ブレーキ時間・連続回数をパラメーターにして、Inspector で何度も調整した |

## 学んだこと
- **コルーチン**：時間のかかる一連の動きを、`yield return` で「待つ」を挟みながら上から順に書けることを学びました。
- **ゲームバランス**：強さは数値（追尾・休み時間・確率）で決まるので、変数にして Inspector から調整できるようにしておくことが大切だと分かりました。
- **チームでの役割分担**：プレイヤーの攻撃は `IDamageable` を通して届くので、プレイヤー担当とお互いのコードを知らなくても連携できました。
