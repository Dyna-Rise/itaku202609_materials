## 担当した機能

### 1. アイテムの購入
- 所持金が足りれば購入でき、足りなければ「お金が足りません」と表示します。
- 持てる上限に達しているときは「これ以上持てません」と表示します。

### 2. スキルの購入（★ 3 段階）
体力・攻撃力・防御力・スタミナの 4 種類のスキルを、それぞれ 3 段階まで強化できます。

| 段階 | 表示 | 倍率 | 値段 |
|---|---|---|---|
| 未購入 | ☆☆☆ | ×1.00 | ― |
| 1 | ★☆☆ | ×1.05 | 300 G |
| 2 | ★★☆ | ×1.10 | 700 G |
| 3 | ★★★ | ×1.20 | 1500 G |

- 一覧には「今の段階 → 次の段階と倍率」を表示して、買うと何が変わるかが一目で分かるようにしました（例：`★☆☆ → ★★☆  ×1.10`）。
- 最大まで買ったスキルは「売切れ」と表示し、色を暗くしています。

### 3. 説明欄
- カーソルを合わせた商品の説明を、画面下に表示します。
- スキルには「装備画面（ドア）で付けると効果が出ます」と案内を足して、次に何をすればいいかが分かるようにしました。

## 工夫したところ

### 表示を「データから作る」ようにした
スキルの名前・星・倍率・値段は、共通のデータクラス `SkillData` から取得しています。
ショップ画面には数値を直接書かないので、値段やバランスを変えるときは `SkillData` だけを直せば済みます。

```csharp
int level = GameData.GetSkillLevel(e.skill);
bool isMax = GameData.IsSkillMaxed(e.skill);
string currentStars = SkillData.GetStars(level);

string infoText = isMax
    ? $"{currentStars}  ×{SkillData.GetMultiplier(level):F2}"
    : $"{currentStars} → {SkillData.GetStars(level + 1)}  ×{SkillData.GetMultiplier(level + 1):F2}";

rows[i].Set(SkillData.GetName(e.skill), infoText,
            isMax ? "売切れ" : FormatMoney(GameData.GetNextSkillPrice(e.skill)),
            isMax ? DisabledColor : PriceColor);
```

### 失敗したときも、理由が分かるメッセージを出した
「買えない」だけでなく、**なぜ買えないのか**（お金が足りない・持ちきれない・売切れ）を出し分けました。プレイヤーが迷わないようにするためです。

### 共通のメニューの仕組みに乗せた
ショップ・装備・クエストの各画面は、共通の親クラス `HomeMenuBase` を使っています（カーソル移動、決定、説明欄、メッセージ表示など）。
自分はショップ固有の「何を並べて、選んだら何をするか」だけを書きました。

## 苦労したところと解決方法

| 問題 | 原因 | 解決 |
|---|---|---|
| 星や倍率の表示が、購入後に更新されない | 行の表示を作り直す処理を呼んでいなかった | 購入後に一覧を描き直すようにした |
| 文字列の組み立てが読みにくい | `+` で文字列をつないでいた | 文字列補間（`$"..."`）と書式指定（`:F2`）を使って整理した |
| ほかの担当と同じファイルを編集して競合した | 共通の UI スクリプトを複数人が触っていた | 自分の担当ファイル以外は触らないルールにし、共通部分の変更は事前に相談するようにした |

## 学んだこと
- **データと表示を分ける**：数値は 1 か所（`SkillData`）にまとめ、画面はそれを読むだけにすると、後から調整しやすくなることが分かりました。
- **プレイヤー目線の UI**：何が起きたか、次に何をすればいいかを文字で伝えることの大切さを学びました。
- **共通クラスの利用**：親クラスが用意している機能を読んで使うことで、少ないコードで画面を作れました。
